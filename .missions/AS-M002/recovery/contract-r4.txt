# AS-M002: Effective root configuration

Prepared contract revision 4, 2026-10-14. The user selected the resolver/schema outcome, documented absent-root defaults, advisory defaults, explicit include/exclude globs, per-path settings with finding policy deferred, TOON and JSON inspection now, and draft 2020-12 with future GitHub release assets. Revisions 1–3 are retained. The mission definition below is ready for execution review; execution/mode and associated authority remain unselected. No packet has been launched.

## Outcome

A user can select a workspace/configuration and relevant path, then inspect validated effective settings from `.anti-slop.jsonc` or documented built-in defaults when the root file is absent. Each value has an explicit origin; invalid inputs produce actionable located errors. TOON-default and explicit JSON inspection encode one effective view. The shared Rust resolver and locally generated JSON Schema agree on the supported contract. This is the first production configuration slice under L02, not an analysis command or published configuration release.

### Concrete local contract

P01 — Read-only inspection: `anti-slop config explain --workspace <dir> --path <workspace-relative-path> [--config <file>] [--format toon|json]`. TOON is the default, including redirected stdout; format selection is explicit and independent of terminal detection. Workspace and path are required. An explicitly requested missing file is an error; root absence without `--config` uses defaults. Unknown arguments, invalid configuration, invalid paths and unsupported formats fail before other work. Preserve the existing top-level help/version/no-analysis behavior.

P02 — Initial field shape: `$schema`, optional `rules`, optional ordered `overrides`. Rule identifiers are R1–R9; values are the scalar strings `off`, `advisory`, `block`. Override fields are `include`, optional `exclude`, and `rules`; include is a nonempty array, omitted excludes mean no exclusions. Rule options and provider/storage/resource-control fields are not supported in this slice and fail explicitly; their owning missions add them under the compatibility gate. These settings identify requested policy, not implemented rules or qualified capabilities.

P03 — One configuration inspection projection is encoded as TOON or JSON with identical settings, identities, origins and errors. Include the selected workspace/path, configuration source or built-in origin, supported contract/schema identity, ordered matching-override identities and all nine effective rule policies with winning origins. For built-in defaults there are no captured configuration-file bytes or applied overrides. Exits: 0 for the returned configuration/default view, 2 for invalid arguments/configuration/identity, 3 for missing explicitly requested files, unreadable inputs or required operational failure. Structured inspection output/errors go to stdout in the selected format; debug/progress diagnostics belong on stderr. Unknown/invalid format selection uses the default TOON error envelope with exit 2. Do not echo rejected credential values or raw input in diagnostics. This view is not an analysis report, policy verdict or durable record.

P04 — Qualify the actual parser, matcher, schema generator and encoder against the technical contract below before dependent implementation relies on them. Numeric bounds and grammar are executable expectations, not claims of existing implementation. Do not silently change the dialect, limits, path bases or compatibility mapping to accommodate a library. Runtime/library ownership, not the CLI adapter, owns configuration semantics.

### Technical qualification contract

T01 — Paths: the workspace must be an existing directory; capture its absolute resolved identity once. `--path` is a nonempty relative path normalized lexically inside that workspace; upward escapes and absolute paths fail. It need not exist, so configuration can be inspected for a future/deleted path. This operation does not read the target's source or follow its symlinks. Relative `--config` is resolved against the selected workspace, independently of cwd; explicitly supplied absolute configuration files are permitted. Resolve the actual configuration file identity before loading, and base patterns on its resolved declaring directory, including a selected symlink target. Do not discover other files. Dangling configuration symlinks and unreadable files are errors, not absent-root defaults. A path outside the declaring directory can be represented by a lexical relative path; literal `..` in a pattern is permitted for an explicitly external configuration, but cannot expand the inspected workspace or access source.

T02 — Glob grammar: case-sensitive UTF-8 paths with `/` as separator. `*` matches within one segment, `?` one Unicode scalar within one segment, and a complete `**` segment matches zero or more path segments, including a final filename. `**/*.ts` includes root-level `.ts` files; `src/**` includes files directly or transitively under `src`. Support literal characters, classes such as `[abc]`, inclusive ranges such as `[a-z]`, class-local negation such as `[!abc]`, and non-nested brace alternatives such as `{ts,tsx}`. Dot-prefixed names are ordinary names. Backslash is a literal character, not a separator/escape convention. Reject leading `!` re-inclusion syntax, malformed classes/alternatives and unsupported `**` placements. Includes are ORed and excludes are ORed, with any exclusion defeating that override only. Compile patterns without walking the filesystem, and demonstrate root-level/nested, dotfile, case, Unicode, overlapping and excluded-then-later-override cases against the qualified matcher.

T03 — Initial bounded inputs: at most 1 MiB of UTF-8 configuration bytes, JSON nesting depth 64, 256 override entries, 1,024 total include/exclude patterns, and 4,096 UTF-8 bytes per pattern/inspection path. Enforce limits before unbounded allocation/recursion, including malformed input; test each actual boundary with independently constructed inputs. Duplicate decoded keys, including escaped-equivalent spellings, are rejected at every object depth. Diagnostics identify the known file and one-based line/column where meaningful, without exposing rejected values. Measure parser/matcher behavior at these boundaries; no whole-analysis or native performance claim follows. A change to this documented contract needs a recorded revision, not a silent larger limit or fallback.

T04 — Schema: initial contract identity `config-v1.0.0`; local generated artifact `schemas/anti-slop.schema.json`. Its JSON Schema dialect is draft 2020-12. Reserve the future asset identity `https://github.com/abdwhb-png/anti-slop/releases/download/config-v1.0.0/anti-slop.schema.json` and map only that exact configuration `$schema` to the supported local contract. Missing/unknown/revision-altered/query/fragment aliases in an existing file are invalid, not fetched. An absent root uses the same built-in contract identity without pretending a file/$schema value was read. The generated schema's meta-schema `$schema` describes draft 2020-12; its `$id` and the project file's `$schema` identify the Anti-Slop contract. Keep these roles distinct. The reserved asset URL has not been published or availability-tested; local qualification explicitly associates the generated artifact in the editor. Public examples/support require later actual immutable publication and a successful fetch. No release, tag, setting or asset is created here.

T05 — Output: qualify one explicitly pinned TOON specification/profile before shipping the inspection encoder, starting from the observed official v4.4 specification and its normative encoder checklist. Freeze the exact source revision/fixture provenance and the supported JSON-domain behavior; package versions remain to qualify through the dependency workflow. Use deterministic field order and stable rule/override ordering. Cover nested origin objects, empty arrays, null/known identities, Unicode, punctuation, quotes, backslashes, multiline/control characters and numeric locations. The required claim is interoperable inspection output under the declared profile; success on these payloads alone cannot establish a universal encoder or completed L05 report codec. Do not replace TOON with TOON-like handwritten text to avoid codec qualification.

Parser, matcher and schema-generation technology may be selected during authorized implementation after bounded qualification against these decisions. Any required dependency change must follow the existing exact-version, release-age and Socket Firewall controls. A blocked download is reported without an alternative unreviewed download path.
