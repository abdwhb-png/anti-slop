## Why working inventories changed during qualification

The real two-file fixture proved that raw Git working diffs can invoke a configured process filter when examining an unchanged staged-only entry with racy timestamps. The first one-file diagnostic lacked that unchanged entry and did not reproduce the effect; its source/result were retained under the `single-file` names. The corrected [probe](worktree/.missions/AS-M003/evidence/P02/probe-git-attributes.json) reproduced it with the actual fixture. `--attr-source` suppressed the worktree attributes but still allowed `info/attributes` to invoke the filter.

The selected implementation therefore uses only cached-index/tree/path metadata and raw object reads in Git, then compares working bytes/modes in Rust. Working baselines come from a cached logical-index comparison or a pinned tree comparison against Git's virtual empty tree. The virtual tree identity is computed without writing an object. Current index paths and nonignored untracked paths complete the candidate set. Intent-to-add is invisible as stored staged content but remains a working candidate. Index flags that could conceal state are rejected explicitly. Relevant inventories and exact mutable bytes are reobserved, with one retry on detected instability.

The mechanism is supported by the real regression and probe; version-matched [Git diff-files implementation](https://raw.githubusercontent.com/git/git/v2.56.0/builtin/diff-files.c) and [Git diff library](https://raw.githubusercontent.com/git/git/v2.56.0/diff-lib.c) identify the working-stat path and cached/tree distinction. The conclusion that cached metadata avoids that working conversion is also directly exercised by successful captures with working, info and external attribute files. No partial attribute-neutralization fallback or project normalization was introduced.

Trade-off: working selectors inspect all bounded baseline/current-index/nonignored-untracked comparison candidates, including unchanged ones, to establish byte equality. They do not turn those candidates into inferred analysis context. Unchanged candidates consume admission and are omitted from retained changes. This increases work relative to an unchecked Git working diff and can reject a small change in a large baseline at the declared limit. The API reports acquired and retained counts separately; no large-repository performance qualification is claimed.

## Finite bounds and achieved observation scope

| Boundary | Implemented behavior |
| --- | --- |
| Admission | 512 input observations/roles per attempt, including unchanged candidates, missing-side observations and repeated context roles; at most 1 MiB per content input and 16 MiB total admitted content. Counts are conservative when Arc data is shared. |
| Metadata | Each baseline/index-path/untracked inventory is at most 2 MiB. Initial working inventories remain bounded; at most one extra inventory is acquired during rechecks. Parsed path/count/string limits are enforced before unconstrained growth. |
| Request paths | At most 512 context and 512 exclusion entries before normalization/deduplication; 4,096-byte normalized paths and supplied configuration arguments. Literal spaces, tabs/newlines and backslashes remain attributable. |
| Content buffers | Git sizes are checked before blob bodies; regular files are bounded during read, including growth. At most one additional 1 MiB input is held for byte verification. |
| Processes | Two-second Git command deadline, bounded stdout and 8 KiB stderr; one command at a time. WNOWAIT preserves leader identity through group signaling, then the direct child is reaped before readers join, including held descendant pipes. |
| Consistency | One pinned HEAD/base, two relevant inventory/byte observations and at most two attempts. A detected repeated change returns explicit instability, never a complete empty capture. |

These are admission/content/buffer limits, not an allocator, Git-internal memory or kernel-enforced RSS quota. Arbitrary blocked filesystem/kernel I/O deadlines, global filesystem atomicity, edits that revert between observations, perpetual freshness, native-overlay coherence and dependency hermeticity are not established. Source symlinks, submodules/unsupported Git kinds, unmerged state and working indexes with assume-unchanged/skip-worktree entries fail explicitly; no missing required context is substituted from index/history. The exact retained selected/context bytes and captured configuration remain inspectable independently of later edits.
