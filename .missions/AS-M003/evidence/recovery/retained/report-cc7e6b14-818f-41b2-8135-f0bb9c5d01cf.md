## Implemented result and design

The new `workspace::capture_staged(&Path, &StagedRequest)` public library operation explicitly selects HEAD-to-index changes and an independent caller-provided working-context list. Its owned read-only result exposes retained changes, both available comparison sides, pinned HEAD, Git blob identities and modes, context, configuration, generation identities and acquisition statistics. A deletion has an absent after-side; an empty file has zero retained bytes; an empty selection is a successful capture with no changes. No analysis outcome is inferred.

The workspace module owns selection, source identities and acquisition. Git plumbing and its process lifetime live in `workspace/git.rs`; descriptor-anchored filesystem acquisition and content accounting live in `workspace/acquire.rs`. There is no new crate, selector registry, generic source-store abstraction or forwarding service. The configuration owner now captures/compiles one configuration and evaluates any number of paths from those same retained inputs. Existing `config::resolve`, policy defaults, ordered overrides, origins, explicit external configuration selection and CLI behavior remain supported by their regressions.

HEAD is resolved once. Two bounded raw index inventories compare that pinned commit to the index. Each returned side is acquired using the inventory's exact object identity; its declared size is checked before requesting its body. A relevant inventory change, configuration-byte change or context-byte change retries once, then reports instability. Object identity, source role/path/mode and actual bytes contribute to source identities; effective configuration contributes to the complete capture identity. Retained ranges are checked against exact source path, role, generation and byte bounds, including empty/EOF, binary and Unicode content. Offsets denote bytes, not character indexes.

Exclusions are normalized literal workspace-relative paths and remain separate from configuration override globs. A conflict returns `CaptureError::Excluded` with the observed paths and roles, without any partial capture or substituted view. Configuration is checked before reading its content, including conflicts through its resolved target. Context is normalized against the workspace root and opened through anchored Linux directory descriptors without following source symlinks, including intermediate components. Explicit external configuration keeps the configuration owner's separate semantics.

The actual Git commands use read-only plumbing, no optional locks, no replacements, no text conversion, no external diff, disabled fsmonitor/hooks and disabled lazy fetch. The environment is cleared except explicitly supplied process settings and executable PATH. Owned processes start their own groups; deadline/output failures kill the group and wait for the direct child. Native code is limited to the Unix group-signal call; filesystem opens use Rust's Unix open options and Linux descriptor paths. No project commands, analyzers, model calls or package installation occur during capture.

Rename detection is disabled. Observable deletion/addition paths and prior/current bytes remain separate evidence without invented correspondence. Only regular/executable Git blobs and regular working-context files are supported; symlinks/submodules and unmerged or unavailable states fail explicitly. Other selectors and complete rename qualification remain outside this packet.

## Proposed enforced limits

These are implemented candidate values for examination, not accepted mission-wide resource qualification.

| Boundary | Limit and accounting |
| --- | --- |
| Retained input count | 512; each HEAD side, index side, explicit context and selected configuration counts separately. |
| Individual content | 1 MiB per source/configuration, including reads of growing files. Git size admission precedes the body request. |
| Total retained content | 16 MiB across comparison sides, context and configuration. |
| Inventories | 2 MiB output per inventory; at most 512 parsed changed paths. Both observations are individually bounded. |
| Request paths | At most 512 context and 512 exclusion entries before deduplication; normalized source paths and the supplied configuration path are bounded to 4,096 bytes. |
| Acquisition | Two attempts, one resolved HEAD; failure returns no partial capture. |
| Owned Git | Two seconds per command; one command at a time; 8 KiB stderr and command-specific bounded stdout. Groups are killed on failure and direct children are waited. |
| Verification buffers | At most one additional 1 MiB input at a time and a second bounded inventory, in addition to retained content. |

These content/buffer bounds do not claim to cap total allocator overhead, compiled configuration structures, Git's internal index/object bookkeeping, kernel memory or whole-tree RSS. Filesystem reads are regular-file reads; a deadline for arbitrary blocked filesystem/kernel I/O is not established. Measurements below describe actual observed owned processes and make no ADR-007 budget claim.
