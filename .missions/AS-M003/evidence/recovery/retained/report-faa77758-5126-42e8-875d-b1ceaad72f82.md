## Git acquisition and design ownership

The actual failing filter evidence establishes that raw working Git diffs can execute a project process filter on a racy unchanged entry. The final planner uses cached logical-index or pinned-tree metadata, current index paths, nonignored untracked paths and raw stored blobs. Rust compares actual working bytes/modes; no clean-filter transformation or substitution is applied. I freshly reran the real helper/preservation scenario rather than relying only on a command-line flag claim. The failed intermediate attribute remedy remains preserved.

This mechanism deliberately reads unchanged baseline/current-index/untracked comparison candidates to prove equality. They consume admission and enter observed capture identity without becoming inferred analyzer context or retained selected changes. A small edit in a large baseline can therefore fail explicitly. This material trade-off is documented and consistent with the approved bounded capture scope; it does not qualify arbitrary large repositories.

Limits are 512 admitted input observations/roles, 1 MiB per content input and 16 MiB total admitted content per attempt; 512 entries per caller list and 4,096-byte paths/configuration arguments; 2 MiB per metadata inventory; at most two attempts; two seconds and 8 KiB stderr per owned Git command. Working acquisition holds baseline/index-path/untracked inventories and at most one extra recheck inventory, plus one bounded content buffer for verification. Arc sharing is counted conservatively by role. These are finite admission/content/buffer bounds, not an allocator, compiled-configuration, Git-internal memory or kernel RSS quota. Arbitrarily blocked kernel/filesystem I/O is outside the Git wait guarantee.

The design hides selection, generation, rename and retry complexity behind `workspace::capture`; private acquisition owns descriptor-safe reads/accounting, private Git owns plumbing/process/blob lifetime, and configuration policy remains in `config`. The public interface does not expose setup sequencing, native/provider representation or a forwarding-service chain. The long capture function follows a single coupled acquisition attempt; splitting it into one-line wrappers would add navigation without removing knowledge. No generic plugin/store framework, speculative interface, universal AST, new crate or duplicated configuration resolver was introduced. I found no separate design defect requiring unrelated refactoring. The mode correction localizes the shared rule in its existing owner.
