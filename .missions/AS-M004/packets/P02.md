# Bounded durable collection admission

## Objective

Complete the library's workspace-local storage admission policy without deleting evidence: explicit configurable budget with the accepted 10 GiB default, warning at 80%, explicit refusal at threshold, and enough reserved capacity to finish each admitted synchronous capture. Two independent processes must not both admit against the same available capacity. A refusal/failed admission leaves prior captures readable and does not change a failure into success. A budget below already retained use must not prevent opening and reading that retained data solely because collection is refused.

## Design constraints

Use the existing records owner and the existing synchronous whole-capture transaction. Explain whether serialization already provides the reservation lifetime; do not add a persistent reservation ledger, multiphase public API, background process or lock framework without a concrete need. Compare extending the existing transaction/journal policy before adding machinery. The schema is still unshipped v1, so complete it coherently without invented migration history.

Account for DB, WAL/rollback journal, shared-memory and other SQLite auxiliary storage plus headroom needed to conclude admitted work. State a conservative accounting/reservation formula and its assumptions; falsify it with real near-boundary writes. journal_size_limit is not a peak bound; max_page_count alone or a sum of source bytes is insufficient. If retaining WAL cannot give a defensible simple bound, selecting a different SQLite journal mode is an available technical choice under the same synchronous SQLite design: justify it with official SQLite behavior and real measurements, not a claim of impossibility. Preserve acknowledged durability and the integrity/atomicity tests. Explain overshoot/failure handling and transient files, not just the final DB size. Distinguish application admission from a hard filesystem quota.

Use explicit path/budget library inputs, not a parallel JSON parser. Keep the public interface small and errors/outcomes useful to callers; no placeholder analysis success or future API. A rejected new capture must have an explicit caller-visible reason. Invalid budget inputs and unavailable accounting/I/O cannot silently enable unbounded collection. Retained reads do not re-read origin files.
